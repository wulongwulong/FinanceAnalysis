- **建议草案**：围绕目标提出的整理方案，尚未定稿。

- **待定**：还没有足够依据确定的细则。

## 二、建议采用的业务主线

**行情与数据检查 → 板块研究 → 标的判断 → 参与条件与参考仓位 → 每日变化 → 历史验证。**

持仓管理使用同一批研究结果，再结合实际持仓，回答已有仓位如何处理。

### 2.1 每天查看的内容

以下页面安排均为建议草案。

| 内容 | 回答的问题 | 至少展示什么 |
|---|---|---|
| 低位转强机会 | 哪些方向经过下跌或整理，开始转强？ | 板块、对应标的、转强依据、确认程度、参与条件、失效条件 |
| 趋势延续机会 | 哪些方向已形成趋势，仍值得跟踪参与条件？ | 板块、对应标的、趋势依据、当前位置、回踩或确认条件、失效条件 |
| 持仓管理 | 已有持仓发生了什么变化，需要如何处理？ | 当前仓位、技术状态、风险变化、目标或上限、调整依据 |
| 今日变化与验证 | 哪些是新出现的信号，之前的信号表现怎样？ | 新触发、升级、降级、失效，以及分类型的历史表现 |

新机会放在主要位置。低位转强和趋势延续分别展示，暂不决定哪一类优先。

### 2.2 业务规则表

下表全部为建议草案；现行代码与这些规则的差异见第三节。

| 编号 | 环节 | 建议规则 | 输出或验证标准 |
|---|---|---|---|
| R01 | 扫描范围 | 首版建议沿用申万一级、二级行业研究方向，具体标的从配置名单中匹配；范围仍待确认 | 明示扫描范围；有机会但未配置对应标的时，保留行业候选并标注待补充 |
| R02 | 数据有效性 | 区分扫描时间、行情截至日期和盘中/收盘状态；旧行情可以供参考，但不作为本次新触发 | 每个结论能追溯至有效行情和运行时段；无法判断时标注数据不足 |
| R03 | 机会分类 | 低位转强和趋势延续采用各自的入选标准；同名标签必须具有明确的策略含义 | 两类机会分别评估；旧策略的 A1/C 不直接混用 |
| R04 | 板块与标的 | 板块用于说明方向，标的自身行情用于判断参与条件；板块入选不等于对应标的可立即参与 | 同时展示板块依据和标的依据 |
| R05 | 关联关系 | 区分直接对应行业和主题参考行业；多行业标的保留关联依据，具体汇总方式待定 | 能解释标的为何关联该方向；不默认最高分细分行业代表整个标的 |
| R06 | 技术判断 | 同一标的、同一策略、同一行情快照使用同一份技术结论；若保留多策略，分别标识并解释分歧 | 机会分析与每日监控不会因重复实现而产生未解释的动作冲突 |
| R07 | 参与准备 | 分开表达机会类型、技术状态和参与准备；采用观察、等待确认、等待回踩、条件满足、信号失效等清楚的表述，具体条件待定 | 看见机会时能知道还缺什么条件；高分不直接等于可买入 |
| R08 | 仓位计算 | 先确定标的参考目标，再应用明确的仓位上限；若网格替代技术目标，应在综合上限之前应用 | 每个百分比有分母、来源和限制理由；网格不会被旧默认目标意外限制 |
| R09 | 持仓处理 | 实际动作结合当前持仓和明确的目标计算；当前没有持仓输入时，只提供条件与参考值 | 没持仓时不显示“继续持有”；目标低于当前仓位时不显示“加仓” |
| R10 | 持仓覆盖 | 持仓标的独立跟踪，不因没有入选新机会、板块过热或没有行业匹配而消失 | 所有已提供的持仓都出现在持仓结果中；缺行情时显示缺失原因 |
| R11 | 风险与失效 | 区分暂不适合新建仓、机会信号失效和已有持仓需要退出；具体风险阈值与退出条件待定 | 可以解释结论改变的原因；失去新机会资格不自动等于卖出已有持仓 |
| R12 | 全球环境 | 首版建议作为方向背景和风险说明；若要参与评分或仓位约束，应另行写出适用对象和条件 | 文本观点不会隐式改变参考仓位 |
| R13 | 记录与提醒 | 区分观察快照、收盘状态和新触发事件；持续满足条件与首次进入条件分别记录；去重规则待定 | 同一快照重复运行不被误计为多个新机会；提醒能说明变化的比较基准 |
| R14 | 历史验证 | 首版建议以有效收盘行情登记正式样本；两类机会分别统计，并区分行业信号与最终标的结论 | 同类型、同策略、同起算口径才合并统计；盘中观察不直接混入正式样本 |

### 2.3 几个术语的统一含义

| 术语 | 含义 | 容易混淆的地方 |
|---|---|---|
| 机会类型 | 低位转强或趋势延续 | 不等于 A1/A2 等阶段，也不等于买入动作 |
| 技术状态 | 行情结构转强、转弱或中性 | 不代表用户实际持有仓位 |
| 参与准备 | 当前参与条件满足到什么程度 | 列入候选不等于满足参与条件 |
| 参考目标仓位 | 规则希望达到的参考水平 | 必须明确相对总账户还是单标的预算 |
| 仓位上限 | 某项约束最多允许多少 | 上限 70% 不代表必须配置到 70% |
| 实际操作 | 当前持仓与目标之间的调整 | 需要当前持仓，不能只由技术状态命名 |
| 新触发事件 | 从不满足条件进入满足条件 | 持续多天满足条件不自动成为多个新事件 |
| 信号表现 | 信号形成后的行情收益与回撤 | 不等于包含仓位、交易成本和成交条件的实际策略收益 |

若沿用现有上限模型，建议的计算顺序是：

```text
标的参考目标 = 命中网格时的网格目标，否则使用技术规则参考目标
综合参考目标 = min(标的参考目标, 板块阶段上限, 位置上限, 单标的总上限)
实际调整 = 结合当前持仓与上述目标判断；缺少当前持仓时不生成实际调整量
```

这仅说明计算顺序，不确认现有比例，也不表示已建立账户组合约束。当前代码中的 `max_integrated_target_pct` 是逐标的限制，不控制全部标的仓位合计。

## 三、整理前代码规则清单

本节记录2026-10-03第一轮整理前的实现，不能直接作为已定稿的新业务规则。已落地变化见第五节；未涉及的阈值、策略和历史口径继续保留。

### 3.1 当前模块的职责

| 模块 | 当前做什么 | 当前没有接上的业务 |
|---|---|---|
| `etf` | 配置 ETF 池的日周线分析、建仓状态、ATR 风险、变化提醒和信号验证 | 不使用行业筛选结果约束仓位；不读取实际持仓 |
| `sector` | 申万行业筛选、映射 ETF/股票/LOF、计算综合仓位、保存行业信号 | 标的动作规则与 `etf` 不同；未保存最终标的决策的验证样本 |
| `fund` | 行业多周期研究、全球环境、多时段历史、A1 验证、ChatGPT 数据包 | 没有具体基金净值和持仓分析；分类与 `sector` 不同 |
| 统一入口 | 顺序运行三个模块，生成报告链接入口 | 没有把三个模块的结果合成为一份机会与持仓结论 |

依据：[统一入口](finance_tools/cli.py)、[ETF 运行流程](finance_tools/etf/runner.py)、[板块运行流程](finance_tools/sector/runner.py)、[基金分析流程](finance_tools/fund/analyzer.py)。

### 3.2 板块分类：两套规则不能直接合并

以下为正常且指标完整的数据下的关键条件。分类按代码判断顺序执行，前一分支命中后不再检查后一分支。

| 分类 | `sector` 现行条件 | `fund` 现行条件 |
|---|---|---|
| A1 | 六个月位置 ≤45%；转强分 ≥8；信号年龄 ≤10 个交易日 | 初步转强；六个月位置 ≤35%；年龄 ≤5 个交易日；15 天位置 35%～80%；一个月位置 ≤80%；RSI 40～60；且未命中 A3 |
| A2 | 未命中 A1；六个月位置 ≤60%；转强分 ≥7；趋势确认 | 状态为初步转强或趋势确认且六个月位置 ≤50%；未命中 A3/A1 |
| A3 | 未命中 A1/A2；15 天位置 ≥88%；三个月位置 ≥65%；趋势确认 | 状态为初步转强或趋势确认且六个月位置 ≤50%；15 天位置 ≥90%、一个月 ≥90%、两个月 ≥95%、RSI ≥65、年龄 >10，任一满足 |
| B | 未命中 A 类且六个月位置 ≤50% | 未命中前述分类；六个月位置 ≤40%，状态为下跌、超跌、筑底或震荡 |
| C | 未命中前述分类：普通/高位观察 | 未命中前述分类；状态为趋势确认、强趋势或高位强势且六个月位置 <80%：趋势机会 |
| D | 没有独立 D 分类 | 六个月位置 ≥80%：高位，判断优先于 A/B/C |
| 其他 | 包含在 C 中 | 观察 |

`sector` 的趋势确认指：价格 ≥MA20、MA20 高于五个交易日前的值、DIF >DEA。

周期与指标也有差异：`sector` 使用 15/20/40/60/80/100/120 个交易日；`fund` 使用 15/21/42/63/84/105/126 个交易日。两套 RSI 和信号年龄算法也不同。仅统一标签或阈值，不能保证结论相同。

当前 `sector` 的 C 会被仓位规则限制为 0；`fund` 的 C 会得到趋势跟踪结论。用户已确认趋势延续也要看，因此新方案不能直接把所有 C 统一为“不参与”。这也不表示 `fund` 的 C 可以直接作为新的趋势入选标准。

依据：[sector 分类](finance_tools/sector/sector_engine.py)、[fund 分类与状态](finance_tools/fund/analyzer.py)、[阶段上限配置](config/sector/settings.json)。

### 3.3 标的动作：日线与周线有两套处理

两套引擎都使用 MACD、KDJ、均线、量能、弱转强等条件，但周线的作用不同。

| 动作 | 两套引擎的基础分数判断，按表内顺序执行 |
|---|---|
| 卖出 | 卖分 ≥5 且卖分 ≥买分+2 |
| 减仓 | 卖分 ≥3 且卖分 ≥买分 |
| 买入 | 买分 ≥6 且买分 ≥卖分+2 |
| 加仓 | 买分 ≥4 且买分 >卖分 |
| 空仓 | 均线空头排列、卖分 ≥2、买分 ≤1；且未命中前述分支 |
| 持有 | 其余情况 |

- `sector` 标的引擎：周线 MACD 动能改善给买分 +1，动能转弱给卖分 +1，再判断动作。
- `etf` 引擎：周线不加进日线买卖分；日线产生原始动作后，周线偏弱时把买入降为加仓、加仓降为持有；周线偏强时把空仓缓和为卖出、卖出缓和为减仓、减仓缓和为持有。
- `etf` 另行输出技术状态和首次建仓状态；这些状态不改变原目标仓位。因此可能同时出现“仅观察”和非零参考仓位。

依据：[sector 标的规则](finance_tools/sector/target_rule_engine.py)、[ETF 标的规则](finance_tools/etf/engine.py)。新方案采用哪套或是否保留多策略，尚未确定。

| 模块 | 登记规则 | 后续表现与回撤 |
|---|---|---|
| `etf` | 行情日等于运行当天，报告模式且本机时间 ≥15:00，才更新正式信号；符合条件的每日信号按日期+代码保留一条；盘中显著变化另记事件 | +5/+10/+20/+40 个交易日行情收益；20 日收盘价峰值到谷值回撤 |

`fund` 当前的时段名称：09:25 前为盘前，11:30～13:00 为午盘，15:00 后为收盘，其余为盘中；按本机时间判断，并非交易日历验证。未来正式样本的有效性应同时核对所属市场和行情状态。

## 四、后续定稿与实施顺序

先按整份规则讨论，不把每个字段变成一道独立选择题。以下细则会影响程序行为，仍需在相应环节定稿：

| 顺序 | 待定事项 | 需要确定的内容 |
|---|---|---|
| 1 | 机会入选口径 | 两类机会各自的主规则、观察与条件满足的分界、排序方式；尤其处理现有 A1/C 冲突 |
| 2 | 机会发现范围 | 是否沿用申万行业+配置标的池，是否扩大具体标的自动发现，以及多行业关联方式 |
| 3 | 仓位和持仓口径 | 百分比分母、目标与上限、比例、持仓输入，以及实际调整和退出条件 |
| 4 | 样本与验证口径 | 正式登记时段、新触发事件定义、比较基准、收益与回撤定义 |

确认对应规则后再实施，按以下例子验收：

1. 一个板块出现低位转强，但对应标的仍弱：保留板块候选，解释标的尚未满足的条件。
2. 一个标的不属于低位策略，但趋势条件成立：能够进入趋势清单，不因旧 C=0 规则被整体排除。
3. 标的处于加速或偏高位置：明确等待或风险条件；不能仅凭机会分高就给无条件参与结论。
4. 同一份标的行情用于机会分析和每日监控：同策略结论一致；多策略分歧带名称和原因。
5. 网格目标 70%、阶段上限 70%、位置上限 80%：在采用网格优先模型时综合目标为 70%，默认 50% 不继续限制它。
6. 当前仓位高于最终目标：不能因为旧技术动作叫“加仓”而显示继续加仓；持仓缺失时不给实际调整量。
7. 持仓标的从机会清单退出：仍能在持仓管理中看到；退出新机会与卖出持仓分别判断。
8. 同一行情快照重复运行、旧行情重新读取：不产生重复新触发；盘中与正式验证样本分开。
9. 两类机会形成验证结果：收益、回撤和样本数量分别统计，策略改变前后的结果可区分。

## 五、第一轮实施进度

## 七、统一分析流程

用户要求把割裂的三个入口合成一个，去掉版本号。本轮统一产品流程、行情和报告，保留明确的技术口径与历史计算。

| 环节 | 当前规则 | 验证标准 |
|---|---|---|
| 启动 | 双击运行分析直接运行完整流程；首页就是完整报告 | 无模块选择菜单、无三报告跳转页、无版本号 |
| 行业研究 | 正常流程只运行原多周期行业研究，用 A1/A2 表示低位转强、C 表示趋势延续 | 不重复调用另一套行业扫描，不混用同名 C 的含义 |
| 标的覆盖 | 行业关联标的与已启用 ETF 监控名单合并；同代码一次取数，行情失败同样只取一次 | 同代码共用行情；每个行业关联保留；未入选新机会的监控标的不消失 |
| 技术判断 | 机会条件沿用日周线加权，监控沿用周线确认；同标的行显示两者及分歧 | 不擅自更改买卖阈值，不用一个动作掩盖不同技术判断 |
| 报告 | 新机会 → 标的判断与监控 → 全球环境 → 历史验证；今日重要变化卡片、全部监控完整表格直接显示，完整字段与详细关联可展开 | HTML、研究摘要、决策包与 CSV 来自同一次扫描；保留日周线、趋势、建仓、仓位、弱转强、波动风险与防守线 |
| 保存 | 新结果在 outputs/analysis，统一入口 outputs/index.html，研究数据包 outputs/chatgpt | 新文件无版本号；原历史与旧报告保留，正常启动不再生成三套报告 |
| 失败 | 首页明确说明本次失败，旧归档仍保留 | 不发布旧快照冒充本次完成 |

默认流程不再执行原 sector 的独立行业分类和综合阶段仓位计算；其代码与历史资料保留供研究。两套证券技术规则的数值、ETF 正式信号登记和行业 A1 验证规则未改变。

本轮形成一个产品与一条业务流程。若后续要进一步统一成单一证券技术动作，仍需明确周线采用加权还是确认，不能通过删掉策略名称来掩盖规则差异。持仓输入已在第八节接入；仓位分母与趋势信号历史验证仍待实施。

## 八、实际持仓维护

实际持仓由用户维护一个账户，输入代码、名称、持有数量（股/份）、平均成本（元/股或份，可留空）和备注。报告中点击“维护实际持仓”，或双击维护持仓.command，进入本机编辑页。持仓保存到 data/portfolio/holdings.json，保存失败保留原文件，旧页面保存时检测维护时间，避免覆盖已经更新的记录。代码统一为6位，同账户重复代码需合并；数量不可为负，清仓可填0或移除。

实际数量不由技术动作或参考仓位反推。未填写不代表空仓；不生成虚拟持仓。数量大于0的持仓纳入同一次行情与技术分析，和机会标的、监控标的共用取数缓存；失败明确显示。维护后报告读取最新持仓，技术分析与CSV、Markdown持仓快照在下一次扫描时更新。离线演示与正式持仓分开。

当前不计算账户仓位比例、自动调仓量或交易流水；仓位分母与现金资产仍未定义。原买卖阈值、参考仓位和历史验证规则保持原口径。
