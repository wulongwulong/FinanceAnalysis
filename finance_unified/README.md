# Finance 分析

一次运行，一份报告：发现低位转强与趋势延续机会，关联具体标的，再查看技术条件、日常监控、全球环境和历史表现。

## 使用

第一次使用先双击 `安装环境.command`。安装完成后双击 `运行分析.command`，直接启动完整分析并打开报告，不再选择模块。

```bash
.venv/bin/python3 main.py --serve     # 分析后打开报告，可进入持仓编辑页
.venv/bin/python3 main.py --holdings  # 直接编辑持仓，不扫描行情
.venv/bin/python3 main.py             # 只生成报告，不启动网页服务
.venv/bin/python3 main.py --demo
.venv/bin/python3 -m unittest discover -s tests -v
```

双击 `离线演示.command` 可查看模拟结果。演示报告写入 `outputs/demo/`，演示历史写入 `data/demo/`，与正式数据分开。

## 维护实际持仓

维护持仓使用**网页表格**，不需要手动编辑 JSON 或 CSV。

1. 双击 `维护持仓.command`，或在运行分析打开的报告中点击 **维护实际持仓**。
2. 点击 **添加持仓**，填写代码、名称、持有数量、平均成本和备注。
3. 点击 **保存持仓**。保存后返回本机服务中的报告，可查看最新持仓。
4. 再运行 `运行分析.command`，更新标的技术分析和持仓 CSV、Markdown、HTML 快照。

数量单位为股/份，平均成本单位为元/股或份；成本不清楚可以留空。清仓可将数量改为0或移除该行后保存。当前支持一个账户、6位证券代码，同一代码合并为一条记录。未填写的标的不代表空仓，系统不会自行生成实际持仓。

保存的数据在 `data/portfolio/holdings.json`，关闭页面后仍保留。编辑期间请保留启动窗口；按 Ctrl+C 可结束本机服务。直接打开静态 HTML 时，请双击 `维护持仓.command` 进入可保存的编辑页。

**保存持仓不会立即重新生成导出文件。** 网页维护的是本地持仓原始数据，CSV 是运行分析时自动生成的快照；手动修改导出的 CSV 不会更新实际持仓。

## 阅读报告

统一入口为 `outputs/index.html`，直接显示完整报告。

1. **新机会**：低位转强 A1/A2、趋势延续 C 分别列出，显示行业位置、建议、风险和实际行情日期。
2. **标的判断与日常监控**：直接展示“今日重要变化”卡片和“全部监控”完整表格，保留日周线状态、建仓条件、参考仓位、风险与防守线。机会对应的 ETF、股票、LOF 与 ETF 监控名单共用行情，关联汇总同代码一行，保留全部行业关联与技术分歧。未入选机会的监控标的继续跟踪。
3. **全球环境**：黄金、原油、美股、美元、美债和 VIX 的背景与风险。
4. **历史验证**：A1 行业信号的收益、超额收益和回撤，保留原有历史样本。

完整字段、行业关联明细、全部行业指标和原始数据可展开查看。新报告标题、归档文件名和通知不再带版本号。

行业机会统一使用现有多周期分类。标的保留两种明确的技术口径：机会条件使用“日线打分、周线加权”，日常监控使用“日线触发、周线确认”。同一行情出现不同动作时，在同一行显示分歧，避免混成一个未经确认的新买卖规则。完整分析不再单独运行另一套行业分类，也不把其 C=0 上限套到趋势机会。

实际持仓由你手工维护，正数持仓会加入分析，即使不在原 ETF 监控名单里。首次参与状态和监控参考仓位仍用于研究；尚未计算账户仓位比例、账户组合约束或实际调仓量。当前支持一个账户、6位证券代码。

## 输出与历史

```text
outputs/
├── index.html                         完整报告入口
├── analysis/
│   ├── 01_每日归档/                    按扫描日与时段归档
│   ├── 02_滚动汇总/                    最近7日、20日摘要
│   ├── 03_最新文件/                    报告、行业、标的、实际持仓、全球资产、决策包
│   └── 04_运行日志/
├── chatgpt/                           一份可整体上传的研究数据包
└── demo/                              独立模拟结果
```

`最新_标的与监控.csv` 每个代码一行；`最新_机会对应标的.csv` 每个行业关联一行。报告、CSV 和两种 Markdown 数据包使用同一次扫描结果。

实际持仓自动导出到以下位置，字段为代码、名称、持有数量、平均成本、备注、维护时间：

| 用途 | 文件位置 |
|---|---|
| 最新持仓快照 | `outputs/analysis/03_最新文件/最新_实际持仓.csv` |
| 给 ChatGPT 的最新持仓 | `outputs/chatgpt/03_最新数据/最新_实际持仓.csv` |
| 按日期与时段归档 | `outputs/analysis/01_每日归档/日期_时段_实际持仓.csv` |
| ChatGPT 扫描记录归档 | `outputs/chatgpt/01_全部扫描记录/日期_时段_实际持仓.csv` |

没有持仓记录时，CSV 只有表头；填写并保存后，再运行分析才会导出相应数据。CSV 的“维护时间”是手动保存持仓的时间，不是行情日期或分析运行时间。离线演示不会读取或覆盖正式持仓，其导出文件位于 `outputs/demo/`。

已有 `data/fund/` 与 `data/etf/` 历史路径继续使用，保留登记条件、收益和回撤口径，避免迁移造成历史丢失。旧报告和旧目录作为历史资料保留，正常启动只生成新的统一报告。

扫描时间与行情日期分别记录。刷新失败可使用有效缓存，报告注明日期与回退状态；旧行情及未确认行情不登记当天正式 A1 样本。历史 CSV 校验失败明确报错，原子保存失败保留原文件。本次扫描失败时首页显示本次错误，不将上一次报告冒充新结果。

## 标的提醒

```bash
.venv/bin/python3 main.py --mode alert
```

保留简短标的提醒。旧 `all / fund / sector / etf` 完整报告命令兼容为同一分析流程，旧 `etf --mode alert` 仍用于提醒；已安装任务无需因入口变化立即重装。安装定时任务的脚本只在手动执行时修改系统任务。

完整分析需要 Python 3.9+、numpy、pandas、requests、akshare；未新增依赖。业务规则和实施边界见 [业务规则](业务规则.md)。

仅用于研究、量化筛选和决策辅助。
